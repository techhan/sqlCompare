# SQL 로그 비교기

ASIS·TOBE SQL을 붙여 넣으면 같은 쿼리인지 판정하고, 다른 곳을 표시한다.

- **주소**: [https://techhan.github.io/sqlCompare/](https://techhan.github.io/sqlCompare/)
- 입력한 SQL은 브라우저 안에서만 처리한다. 저장하거나 외부로 보내지 않는다.
- [변경 이력](CHANGELOG.md)

---

## 1. 사용법

1. 왼쪽에 **ASIS**, 오른쪽에 **TOBE** SQL을 하나씩 붙여 넣는다.
2. 상단 **판정**을 확인한다.
3. 다르면 **검토 항목**을 본다.
4. 다음 쿼리를 비교할 때는 **초기화**를 누르거나 내용을 변경하면 된다.

> ⚠️ **SQL문만 넣는다.** 로그의 시간, 스레드, 로거 이름, 실행 시간 같은 정보가 섞이면 "다름"이나 "오류"가 나온다.
> 파라미터는 값으로 들어간 상태여야 한다. `?`나 `:1`이 남아 있으면 값으로 바꿔서 넣는다.

## 2. 판정

| 판정 | 의미 | 할 일 |
|---|---|---|
| 🟢 같음 | 정규화 후 완전히 같음 | 없음 |
| 🔵 같음 (허용 차이 n건) | 허용 규칙에 해당하는 차이만 있음 | 검토 항목을 훑어본다. **U2는 반드시 확인** |
| 🔴 다름 (n곳) | 허용되지 않는 차이가 있음 | 검토 항목의 빨간 줄을 확인한다 |
| ⚫ 오류 | 입력이 비었거나 따옴표·주석이 닫히지 않음 | 입력을 고친다 |

## 3. 화면 보는 법

| 영역 | 내용 |
|---|---|
| 정규화 결과 | 비교에 실제로 쓴 SQL. 🔴 빨강 = 다름, 🔵 파랑 = 허용, `▸` = 반대편에만 있는 위치 |
| 검토 항목 | 다름은 위쪽에 한 줄씩, 허용은 규칙별로 묶어서 보여준다 |
| 적용 규칙 | 규칙마다 ASIS·TOBE에서 몇 번 적용됐는지 보여준다 |

**클릭 이동**
- 정규화 결과의 하이라이트 → 검토 항목의 해당 줄
- 검토 항목의 줄 → 정규화 결과의 해당 위치
- 검토 항목의 규칙 이름 → 적용 규칙 표의 해당 규칙

## 4. 값 무시

켜면 문자열·숫자 값이 달라도 같다고 본다.

| 문장 | 기본 상태 | 이유 |
|---|---|---|
| INSERT·UPDATE·DELETE | **자동 켜짐** | 같은 데이터로 두 번 실행할 수 없음 (키 중복, 이미 삭제됨 등) |
| SELECT | 꺼짐 | 조건값까지 검증해야 함 |

필요하면 상단 스위치로 직접 켜고 끈다.

## 5. 주의할 점

- **U2(updatewhere 조건)가 나오면 확인한다.** DataWindow 저장이면 정상이다. 스크립트에 직접 쓴 UPDATE라면 업무 조건이 빠진 것일 수 있다.
- **`'4'`와 `4`는 다르다.** 숫자 함수 옆이면 결과가 같지만, 문자 컬럼 옆이거나 SELECT 결과값이면 결과가 달라질 수 있다. 비교기는 컬럼 타입을 모르니 항상 "다름"으로 표시한다.
- **의도한 차이도 "다름"으로 나온다.** 예: TOBE에서 DECODE 대신 공통코드로 처리한 경우. 확인했으면 넘어가면 된다.
- 쿼리는 한 번에 하나씩 넣는다. 여러 쿼리가 섞인 로그는 비교할 수 없다.

## 6. 규칙 상세

### 정규화 (표기 차이 제거)

| ID | 규칙 |
|---|---|
| N1 | 주석(`--`, `/* */`)을 제거한다. 따옴표 안은 주석으로 보지 않는다 |
| N2 | 힌트 `/*+ */`는 지우지 않고 비교한다 |
| N3 | 공백·탭·개행은 구분자로만 쓴다 |
| N4 | 따옴표 밖 단어는 대문자로 통일한다 |
| N5 | 문자열 값은 원문 그대로 비교한다 |
| N6 | 연산자 사이 공백을 붙인다: `< >`→`<>`, `> =`→`>=`, `< =`→`<=`, `! =`→`!=` |
| N7 | 끝의 `;` 하나는 무시한다 |
| N8 | NBSP·전각 공백 같은 특수 문자는 지우지 않고 `[U+XXXX]`로 표시한다 |
| N9 | 큰따옴표 안이 전부 대문자면 따옴표 없는 이름과 같게 본다 (`"COL"` = `COL`) |

### 허용 (공통 차이)

| ID | 대상 | 조건 |
|---|---|---|
| A1 | UPDATE_DATE | TOBE 값이 `SYSDATE`면 허용 (UPDATE SET, INSERT 값만) |
| A2 | UPDATE_MAN | 양쪽 값이 모두 문자열이면 허용 (ASIS 사용자명 → TOBE 사용자 ID) |
| A3 | `'0' AS CHK` | TOBE 메인 SELECT 목록에만 있으면 허용 (멀티로우 삭제용) |
| A4 | DELETE FROM | `DELETE` 바로 뒤 `FROM`이 한쪽에만 있으면 허용 |
| U1 | UPDATE SET | 순서 없이 컬럼 단위로 비교한다. TOBE에만 있는 컬럼은 허용하고, ASIS에만 있는 컬럼은 다름 |
| U2 | UPDATE WHERE | ASIS에만 있는 `COL = 값`, `COL IS NULL` 조건 중 COL이 TOBE SET 컬럼이면 허용 (PB updatewhere) |
| V1 | 값 무시 | 4장 참고 |

### 하지 않는 것

- 값 형식 통일: `'10'`과 `10`, `1.0`과 `1`은 다르다
- 컬럼·조건 순서 재배열 (UPDATE의 SET·WHERE만 예외: U1·U2)
- 의미가 같은 다른 표현 통일: `!=`와 `<>`, alias, JOIN 문법, NVL과 COALESCE

## 8. 관리

**허용 규칙 추가 기준**
전환 원칙에서 **공통 차이로 정한 것만** 추가한다. "이번 쿼리를 통과시키려고"는 기준이 아니다. 허용이 늘수록 진짜 차이를 놓칠 위험도 커진다.

**수정 방법**
- 허용 규칙: `index.html`의 `ALLOWED_RULES`(A1·A2), `EXTRA_TOBE_RULES`(A3)
- 수정 후 `VERSION`을 올리고 `CHANGELOG.md`에 기록한다
- 예전 버전이 보이면 `Ctrl+F5`로 새로고침한다
